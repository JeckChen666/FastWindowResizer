# FastWindowResizer 第一版规划

## 1. 背景与目标

远程使用 Windows 电脑时，分辨率、显示器连接状态或缩放比例变化，可能导致应用窗口移出可见区域，或缩小到无法操作。用户希望在不关闭应用的情况下，快速找回窗口。

本工具运行在目标电脑的当前交互式用户会话中，常驻系统托盘。用户右键点击托盘图标，选择一个窗口，即可将其恢复到当前操作屏幕中央，并在必要时调整大小。

主要入口只依赖鼠标操作，不依赖可能被其他应用占用或拦截的快捷键。

第一版成功标准：正常桌面环境下，用户通过“右键托盘 → 点击目标窗口”两次点击，找回一个位置或尺寸异常的普通应用窗口。

## 2. 已确定的范围

### 第一版包含

- 系统托盘图标和右键窗口列表。
- 每项显示应用图标与窗口标题；标题缺失时使用可获得的应用名称作为补充。
- 同一应用的多个独立窗口分别列出，最小化和屏幕外窗口也能被选中。
- 点击后恢复目标窗口、居中，并按下述规则修正异常尺寸。
- 多显示器、不同 DPI 缩放比例下的基本支持。
- 菜单底部提供“退出”。
- 单实例运行，避免重复启动产生多个托盘图标。
- 资源管理器重启后恢复托盘图标。
- 操作失败时给出简短提示，不阻塞托盘程序。

### 第一版暂不包含

- 全局快捷键、搜索框、窗口实时缩略图和自定义设置界面。
- 自动扫描或自动修复、批量找回、布局保存和恢复。
- 自定义尺寸预设、撤销和自动更新。
- 跨会话控制、跨虚拟桌面搬移、浏览器标签页级操作。
- 对游戏独占全屏、系统安全桌面、无响应应用等特殊场景的全面支持。

后续功能以实际使用反馈为依据，不提前扩展架构。

## 3. 操作行为

1. 启动后只显示托盘图标，不显示主窗口。
2. 用户右键托盘图标时，记录鼠标所在显示器，作为本次找回的目标显示器。
3. 按需获取窗口列表并弹出菜单。菜单必须完整落在可见工作区内；窗口较多时支持滚动。
4. 用户点击某个窗口后关闭菜单，重新检查窗口是否存在，再执行找回。
5. 成功时不弹出额外确认；失败时简短说明，例如窗口已经关闭、应用未响应或操作受限。

显示器在菜单打开后断开时，重新选择仍有效的显示器，最后回退到主显示器。目标区域使用排除任务栏后的工作区。

### 位置与尺寸规则

- 普通窗口：保留合理尺寸并居中。
- 最小化或最大化窗口：先还原为普通状态，再计算尺寸和位置。
- 可缩放窗口：尺寸超过工作区时缩小至适合工作区；异常过小时重置为工作区宽高的约 80%。
- 初始“异常过小”判定：还原后的宽度小于 240 DIP，或高度小于 160 DIP。阈值只用于用户主动选择的可缩放窗口，以常量保存并根据实测调整。
- 固定尺寸窗口：只移动，不强制修改窗口样式；尽量保证标题栏和主要操作区域可见。
- 尊重应用的最小、最大尺寸限制。应用拒绝调整时不反复强制尝试。
- 尝试把窗口带到前台，但不设置永久置顶；系统限制激活时，不将激活失败等同于移动失败。

所有尺寸比较使用一致的 DPI 坐标体系。多屏坐标可能为负数，不能把负坐标直接当作异常。

## 4. 窗口列表规则

列表以 Alt+Tab 的“打开的窗口”体验为参照，不以进程列表为依据，也不承诺与不同 Windows 设置下的 Alt+Tab 内容和顺序完全一致。

- 枚举桌面应用顶层窗口，结合窗口样式、所有者和活动弹出窗口关系筛选。
- 保留可切换的普通应用窗口，包含最小化和位于屏幕外的窗口。
- 不因窗口与当前屏幕没有交集而将其过滤掉。
- 排除桌面、任务栏、隐藏辅助窗口以及本工具自身窗口。
- 不将工具窗口一律当作独立任务；结合所有者关系判断，避免漏掉需要操作的对话框。
- 存在模态对话框时，优先处理实际阻塞交互的活动对话框，避免仅移动被禁用的主窗口。
- 默认显示当前虚拟桌面的窗口；使用公开接口判断，不依赖未公开的 Shell 接口。
- 浏览器多个独立窗口分别显示，窗口内部标签页不单独显示。
- 初始沿用系统枚举顺序，不维护完整的最近使用历史。

筛选结果需要用用户实际常用应用与 Alt+Tab 对照验证；边缘兼容问题以具体应用为单位修正。

## 5. 技术选型与环境

### 选型

- 语言：C#。
- 框架：.NET 10 LTS，目标为 Windows x64。
- 界面：WinForms 的 ApplicationContext、NotifyIcon 和 ContextMenuStrip。
- 窗口控制：通过 P/Invoke 调用 Win32 API；虚拟桌面判断使用公开 COM 接口。
- DPI：启用 Per-Monitor V2，并验证跨缩放比例移动。
- 依赖：优先使用 .NET 自带库，不引入第三方 UI 框架、浏览器运行环境或依赖注入框架。

### 当前环境检查结果（2026-09-13）

| 项目 | 检查结果 |
| --- | --- |
| 操作系统 | Windows 11 专业版，x64，Build 26200 |
| .NET SDK | 8.0.423 |
| Windows Desktop Runtime | 8.0.29 |
| WinForms 模板与引用包 | 已安装 .NET 8 对应组件 |
| .NET 10 SDK | 尚未安装，正式编码前补齐并验证 |
| 项目初始状态 | 空目录 |

.NET 8 可用于验证，但将于 2026-11-10 结束支持，因此新项目采用 .NET 10 LTS。使用命令行构建，不要求安装完整 Visual Studio。

### 构建与交付

- 使用 Release 配置构建，面向 win-x64。
- 默认交付自包含的便携文件夹，解压运行，目标电脑不必另装 .NET Desktop Runtime。
- 自包含会增加磁盘体积；不将包体大小与常驻内存混为一谈。
- 不为单文件外观引入额外打包复杂度，第一版不使用 Native AOT 或激进裁剪。
- 默认普通用户权限启动。受权限限制的目标窗口明确提示，必要时由用户手动以管理员身份重启工具，不自动提权。

## 6. 最小代码组织

保持一个应用项目，不拆分多层工程。

```text
FastWindowResizer/
  docs/PLAN.md
  docs/VALIDATION.md
  README.md
  FastWindowResizer.csproj
  app.manifest
  Program.cs               启动、DPI、单实例
  TrayApplicationContext.cs 托盘生命周期、菜单与操作提示
  WindowService.cs         窗口筛选与找回逻辑
  NativeMethods.cs         Windows API 与结构定义
  StartupSettings.cs       当前用户开机自启配置
  scripts/                 图标导出工具
  Assets/                  托盘图标
```

实现过程中允许按可读性微调文件边界，不新增不必要的抽象层。

## 7. 资源与稳定性约束

- 闲置时只等待系统消息，不运行周期扫描、网络请求或持续日志写入。
- 窗口列表只在打开菜单时刷新；菜单关闭后释放不再使用的图标和菜单资源。
- 获取应用图标或跨进程信息时避免无限等待，失败时使用默认图标。
- 移动窗口避免同步等待目标应用导致界面卡死；结果验证使用有限等待，不循环强制修复。
- 操作前重新校验句柄和关联进程，降低窗口关闭或句柄复用导致误操作的风险。
- 托盘图标、菜单和原生资源正确释放；显示变化后重新读取工作区。

性能验收以 Release 构建的真实进程为准：

- 闲置 CPU 应接近零，无持续明显占用。
- 内存预期为几十 MB 量级，不预先承诺固定数值。
- 记录启动稳定后、打开一次菜单后，以及反复打开关闭菜单后的工作集、私有内存和句柄数量。
- 重点确认资源不随操作次数持续增长，不通过强制清空工作集制造低内存读数。

## 8. 实施顺序

1. **准备环境**：安装并验证 .NET 10 SDK，创建最小项目和 DPI 清单。
2. **托盘与列表**：完成单实例、托盘菜单和接近 Alt+Tab 的窗口筛选。
3. **找回行为**：实现状态恢复、目标显示器选择、居中与异常尺寸修正。
4. **兼容与资源检查**：验证远程会话、多屏缩放、窗口关闭和无响应等场景。
5. **交付**：生成便携 Release 包，补充 README 中的运行方式、限制和实测资源数据。

第一版已于 2026-09-13 实现并生成便携发布版本；实际验证结果及尚待实测的场景见 VALIDATION.md。

后续增量：按用户要求增加托盘菜单“开机自启”开关，使用当前用户的 Run 注册表项保存当前 EXE 路径。默认关闭，仅在用户点击时修改配置；不引入后台轮询或额外服务。

## 9. 验收清单

| 场景 | 预期结果 |
| --- | --- |
| 启动、重复启动、退出 | 只有一个托盘实例；退出后资源释放 |
| 右键托盘 | 菜单位于可见区域，图标与标题可辨认 |
| 普通应用与多个独立窗口 | 与 Alt+Tab 的窗口范围基本一致，无大量辅助项 |
| 窗口完全位于屏幕外 | 仍出现在列表，点击后回到目标屏幕 |
| 最小化、最大化、异常小尺寸 | 还原并按规则居中、调整 |
| 固定尺寸或模态对话框 | 找回可操作的对话框，不强制改变固定尺寸 |
| 双屏、负坐标、不同缩放比例 | 目标屏幕选择正确，位置与尺寸无明显偏差 |
| 远程重连或分辨率变化 | 菜单和找回结果均位于当前有效工作区 |
| 打开菜单后目标窗口关闭 | 安全失败并提示，不崩溃 |
| 目标应用无响应或操作受限 | 工具仍可使用和退出，不无限等待 |
| 资源管理器重启 | 托盘图标重新出现 |
| 反复打开菜单与执行找回 | 内存、句柄数量无持续增长趋势 |

可自动验证的尺寸与居中计算覆盖负坐标、小工作区和不同 DPI；实际窗口行为采用受控测试窗口及常见应用手动验证。移动用户真实工作窗口的测试需在明确的测试范围内进行。
